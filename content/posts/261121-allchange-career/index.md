## 就職って「大人」なのか？

**「大人になれ」** と言われて **「了解、では就活を始めます」** と返す人間がいたら、流石にそいつは”ズレている”と見做されても仕方がないでしょう。

例えば『ヱヴァンゲリヲン新劇場版:破』において[^1]碇ゲンドウはシンジに対して「大人になれ」と吐き捨てましたが、それを受けたシンジが **「分かったよ父さん。社内公募制度を探して、エヴァに乗らなくてもいいような職種に転属を願い出ようと思う」** みたいに応じたら流石にキモすぎると思います。

「就職すること」は「精神的な成長」とは別のベクトルを持っており、「大人であること」の十分条件でもありません。しかしながら、世間的にほぼ **就職は成長の必要条件のように扱われている** ことには疑いようがないでしょう。定職だけ得ている子供じみた人間になってしまうのは最悪ですが、だからといって **「定職に就いていないガキみたいな人間」** のままでいるのはもっと最悪だ、というわけです。

ということで、あまりにもヘンすぎ、資本主義的すぎ、そして **就活早期化の走狗** すぎる考え方かもしれませんが、私は **「大人になるためにまず就活を終わらせよう」** と決めました。

## 就活のギアを上げた（工学的に正しい表現）

かなり志望度の高い会社からご縁をいただき、 **就職活動が一段落しました。** 今は脳味噌のエンジンに直結する就活ギア（←何？）を巡航用のものに上げ、アクセルを抜いて少しずつ速度を落としているところです。

↑の説明だと車好きしか理解できないと思うので具体的に書くと、選考にエントリーする企業を

1. 元々第一志望群であり、今回お声がけいただいた会社とは別のベクトルで働きがいを感じる企業
2. 明らかに自分の実力以上の企業

に絞ったということです。今まではあらゆる会社の新卒採用マイページから（それこそ1日100件ほど）告知メールが届いていたのですが、昨日一気に登録解除した結果ぱたりと通知が止みました。このままゆるりと続けていき、 **来年3月末には完全に就活を終活（激オモロギャグ）** しようかと考えています。

## 「敗因」を減らすためにやったこと

ここから「何故私がこの時期に就活を終えられそうなのか」を意気揚々と書き連ねることもできるでしょうが、そもそも就活はかなり「運」や「縁」が絡んでくる営みです。 **勝ちに不思議の勝ちあり、負けに不思議の負けなし** という言葉があるように、失敗についてはいくらでも事後諸葛亮できる一方で、成功について理由を見出そうとするとどんどんズレてしまいます。

なので、「どのように上手く行ったか」ではなく「どのように失敗リスクを減らしたか」について以下に4点ほど挙げてみます。参考になれば幸いです。

### 1. 3年春までにたくさん単位を取る

「それができたら苦労はしない」と言われるかもしれませんが……

私はほぼ兼サークルをしておらず、趣味もカブの運転と東方ぐらいしかない **無キャ** です。図書館情報学は好きな学問分野ですが、積極的に授業を聴講しまくって学びを深めたり、院進を志したりするほどの熱意は持っていませんでした。

というわけでやたらと時間だけは余っていたので、 **3年春学期の段階で卒業要件におけるほぼ全ての単位を取り切ってしまいました。** 今は週に5コマ（必修3コマ+選択必修2コマ）しか授業が入っていません。

> [!NOTE] 注意
> 念のため、弊学類を擁護するために書いておくと、いくら知識情報・図書館学類が緩めな学類だといっても適当に履修しているだけでは3年春で単位を取り切ることはできません。
> 
> 私は長期休暇に暇を持て余していたので、オンデマで履修できる授業を取りまくり、卒業要件を満たす「他学群の授業科目」で15単位ほど埋めています。

外資系やコンサル系を除き、ほぼ全ての企業は **3年春の間はどれだけ早くとも「夏インターンに向けた選考」しか行われず** 、その選考もガチなものは少ないです。つまり **3年の春学期は「申し込みボタン」を押すだけのフェーズ** なので、3年夏休み突入と同時に単位をおおかた取り終わるような計画で履修を進めれば問題なく就活を進められると思います。

### 2. 面接前に床屋に行く

面接前に床屋に行くことで、身だしなみに関する課題を金銭で解決することができます。

私はオタクくんなのでヘアセットの経験が極めて乏しく、いくらスーツを着こなしたとて **このままだと特殊詐欺の受け子みたいな格好** になってしまうのではないか？という危惧がありました。

そこで、早朝から都内で営業しているビジネスマン向けの床屋を予約し、

> **「私はヘアセットについて無知な学生で、今から[業界・業種]の最終面接があります。とりあえず髪を適当に伸ばしてきました。好きなように弄っていただいて構わないので、『これで落ちたら、原因はお前に清潔感が足りないからではなく、お前自身の人格・能力に問題があるからだ』と言い切れるように整えてください。」**

と理容師さんにお願いしました。

身だしなみに自信がない人は、私のように **床屋に行った脚でそのまま面接に向かう** と良いと思います。

### 3. Twitter（現X）を見ない

「投稿」はしてもいいと思いますが、「閲覧」、特に **「おすすめタイムラインの閲覧」は百害あって一利なし** だと思います。

Twitter（現X）では就活に関する”生の情報”を多数得ることができるように思われますが、冷静に考えると役に立つのは企業の選考開始の告知ぐらいで、それ以外は「28卒界隈」とかいう ~~浪人界隈の3年後みたいな~~ 内輪の揉め事しか流れてこず、 **意味がありません。**

私は[分散型SNSの個人サーバーを運用している](posts/251217-fediverse/#結論)ので、日常的な発言は全てそちらで行うことで投稿欲から閲覧欲まで全て発散させていました。アカウント作りたい人がいたら招待コード発行するのでDMください。

### 4. 就活に関連する全てのテキスト／コンテキストを記録する

> [!CAUTION]
> こっからオタク語りです！ごめん

夏辺りまで **紙のメモ帳** で選考状況を管理していたのですが、途中でパンクしかけてしまいました。

元々、 **普段の大学の授業ではObsidianを使ってノートを取っていた** ため、これを流用すればもう少し整然と自分の状況を把握できるのでは？と思い立って色々と試行錯誤していました。

この記事ではその集大成をお伝えします。私はObsidianを使いましたが、 **Notion** でもいいと思います。可能な限りシンプルな構成にしたので、誰でも参考にできるはずです。

#### 準備するもの

- Obsidian本体
- Kanbanプラグイン
- （以下はオタク向け）
	- Git環境

	- LLMの課金プラン

#### Obsidianの基礎知識

Obsidianとは、 **Markdown形式で端末内にメモを記録していくアプリ** です。Markdown形式とは、AIがよく言う
```markdown
それって、 **本質** です。以下に例示すると、

- ほげ
- ふが
- ぴよ

参考になりましたか？
```

みたいな書き方のことです。Obsidianで作成したデータはローカルに保存されていくので、いきなりアプリが壊れたりデータを移行したくなっても比較的なんとかなりやすいのが特徴です。

重要な考え方として、 **絶対に孤立したノートを残さない** ことを意識してください。ノート内に`[[hogehoge]]`と半角鍵括弧を記入することでリンクを作成することができるのですが、 **「どこにもリンクを繋げず、どこからもリンクが繋がっていない」** ノートを作るのはやめましょう。少なくとも一方的にリンクが繋がっていれば、サイドバーの「バックリンク」も駆使して双方向を辿ることができます。

#### 事前準備・ディレクトリ構造

Obsidianをインストールし、適当な場所にVaultを作ります。Vault内に以下のような形でフォルダとノートを用意してください[^2]。

```
Vault/
├─ 選考プロセス別/
│└─ 20YYMMDD_企業A_エントリーシート.md
├─ 企業別/
│└─ 企業A.md
├─ 日報/
│└─ 20YY-MM-DD.md
└─ タスクリスト.md
```

そして`タスクリスト.md`をKanbanプラグインの対象にして、

- 未着手・出直し
- 選考中
- 内定
- 不採用・断念

の列を作れば準備完了です。

#### 運用方法

まず、応募したい企業において何かしらの選考が始まったら、`企業別`フォルダに`企業名.md`ノートを作成します。そこに

```markdown
## タイムライン

〇月〇日：[[20YYMMDD_企業名_選考プロセス.md]]
```

のように記入します。同名のノートを`選考プロセス別`フォルダ内に作成し、

- エントリーシートの設問
- 面接の想定問答
- インターン中のメモ

など、就活中に得た情報をなんでも[^3]記録していきます。

`タスクリスト.md`には選考プロセスに合わせて

```markdown
[[企業名]]：インターンシップ参加 YY月DD日
```

などと短く書いたカードを追加・移動していきます。

#### これの何が嬉しいのか

ここまでお伝えした行為は一見すると不必要なメモ魔というか、 **「綺麗なノートを作ることに拘泥して成績が悪い人」** を再現しているようにも思われるかもしれませんが、案外就活が進むにつれて活きます。

例えば

- 通過した/落選した **過去のエントリーシートを比較したい**
- カレンダーには印がついているものの、具体的に **どのようなイベントだったか忘れた**
- 本選考に申し込むにあたり、 **インターンの経験を語りたいがうろ覚え** である

といった状況において、過去の記録が紙のメモ帳の何倍も早く正確に引き出せるのは非常にパワフルです。 **図書館情報学、最高！**

#### おまけ：コーディングエージェント用ファイル

> [!WARNING]
> 以下はガチでオタク向けです！
> 
> 加えて、LLMを使って就活用フォルダにアクセスさせる際は必ず
> - 「モデルを改善するために入力を学習する」的な設定がオフになっていること
> - 深刻な個人情報、社外秘として渡された資料がVault内に存在しないこと
> 
> を確認してください。 **就職する前からシャドーAIで情報漏洩** なんてやらかしたら洒落になりません。

私はClaude Codeを使って **「Vibe 就活」** も試みました。

純正のメモリ機能に頼らず、 **コーディングエージェント側の記憶は都度ドキュメントを読み直させる形で植え付けるほうが安定する** ことに気付いたので、最終的に以下のような運用となりました。

```markdown
# 就活アシスタント用 指示

このフォルダは [ユーザー名]（XXXX年XX月卒予定の学部生）の就活管理フォルダ。[ユーザー名]はObsidianを用いてメモの管理を行っている。
CLAUDE はここで、ES作成・選考管理・面接対策・戦略相談を手伝う。

@_memory/profile.md
@_memory/preferences.md

## 助言の方針

- 表面的な一般論ではなく、実際の新卒就活（早期選考、インターン経由選考、企業ごとの評価軸）を踏まえて助言する。
- 本人の戦略は[略]。[業種]系を見ている。この前提に沿って考える。ただし戦略に無理や見落としがあれば遠慮なく指摘する。
- 企業の制度・日程・募集要項など現在の事実は、記憶で答えずに公式ページを確認してから使う。

## 回答前に読むもの

1. まず `_memory/INDEX.md` を見て、質問に関係するファイルだけを読む。全部を読まない。
2. 就活全体の方針は `就活ハブ.md`、企業ごとの状況は `タスクリスト.md` と `選考プロセス別/` を見る。
3. 直近の流れが必要なときは `日報/` の最新数日分を読む。
4. 「覚えていない」「情報がない」と答える前に、該当しそうなファイルを読む。
5. 基本的にClaude Code側のメモリ機能は無効化しているはずだが、設定漏れなどで上記_memory内の手動メモリとClaude Code側の自動メモリが混在する可能性がある。手動メモリを優先させること。

## 書き込みのルール

- `_memory/` に書くのは、本人が会話の中で述べた事実・決定・好みだけ。Claude の推測、提案、調べた情報は書かない（提案を本人が採用した場合は「〜にすると決めた」として書く）。
- 1回だけ出た雑談的な話題は書かない。人・所属・進行中の選考・決定事項は1回でも書く。
- 古くなった事実は消さずに「（以前は〜）」の形で更新する。本人が「忘れて」と言ったものは行ごと消す。
- ファイルを追加・削除したら `_memory/INDEX.md` の1行説明も更新する。説明は「何が入っているか」が分かるように、企業名などの固有名詞を含めて書く。
- 会話中に自分から `_memory/` を書き換えるのは、本人が「覚えて」「直して」と頼んだときだけ。それ以外は `/wrap` でまとめて行う。
- `日報/` の過去の日付のファイルは書き換えない。追記は当日のファイルだけ。
- `就活ハブ.md` と `自己分析*.md` は本人の文書。大きな書き換えは差分を見せて了承を得てから行う。

## タスクリスト.md（Kanban）の扱い

- Obsidian Kanban プラグインの書式。先頭の frontmatter（`kanban-plugin: board`）、`## レーン名` の見出し、`- [ ] カード` の形、末尾の `%% kanban:settings ... %%` ブロックは絶対に崩さない。
- 許される操作は、カードの追加、カードの別レーンへの移動、カード本文の小さな修正だけ。レーンの追加・削除・並べ替えはしない。
- 編集の前後で、レーン数とカード数が想定どおりか確認する。

## 作業上の約束

- ES など字数制限のある文章は、Python で字数を数えてから提示する。
- 未確認の数値は `【N】` のようなプレースホルダにする。事実を作らない。
- `git push` はしない。コミットは `/wrap` の中だけで行う。
```

```markdown
   - 変更したファイルと、各ファイルに追加・変更した行を一覧で示す。
```
